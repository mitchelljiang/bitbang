# WS2812
*WS2812B addressable RGB LED (NeoPixel)*

## Summary
Addressable LED strips driven by a single data line. Every bit is a high pulse followed by a low one, 1.25 µs in all: a short high pulse is a 0 and a long one is a 1. Each LED keeps the first 24 bits it receives, its green, red and blue brightness, and passes everything after them to the next LED. A long low period latches the colors.

## Used in
LED strips and rings, sold as NeoPixels by Adafruit, in lighting, displays, wearables and hobby projects.

**Tags:** asynchronous, single-ended, push-pull, simplex, daisy chain, chip-to-chip

## At a glance
- **Clock:** None. Each bit begins with a rising edge, and the LED tells a 0 from a 1 by how long the line stays high.
- **Wires:** One data line (DIN) plus 5 V power and ground. Each LED drives its own DOUT into the next LED’s DIN.
- **Drive:** Push-pull. A 5 V LED often reads 3.3 V logic correctly, but the datasheet asks for 0.7 × VDD, so a level shifter is safer.
- **Duplex:** Simplex: data only flows from the controller down the chain. The LEDs never answer.
- **Topology:** A daisy chain: the controller feeds the first LED, and each LED regenerates the signal for the next.
- **Addressing:** None. An LED’s position in the chain is its address: the first 24 bits go to the first LED, the next 24 to the second, and so on.
- **Flow control:** None. The controller sends whenever it likes; holding the line low for the reset time makes every LED show its new color at once.
- **Error checking:** None. A timing error shows up as a wrong color.
- **Speed:** 800 kbit/s, so 30 µs per LED: about 1,000 LEDs at 30 frames per second.
- **Reach:** Centimeters to a few meters between the controller and the first LED. Each LED regenerates the signal, so the chain itself can be long; power is usually the limit.

## Strengths
- One data pin drives hundreds of individually colored LEDs.
- No addresses to configure: position in the chain decides which color goes where.
- The signal is regenerated at every LED, so it stays clean along long strips.

## Limits
- Tight timing (±150 ns) is hard to meet by toggling a pin in software with interrupts enabled; SPI, PWM with DMA, or a dedicated peripheral is usually used instead.
- Updating one LED means resending every LED before it in the chain.
- No error checking or feedback: the controller cannot tell whether an LED received its color.

## Settings
- **Colors** — One color per LED, each written as six hex digits, RRGGBB, as in HTML. They are sent green first, then red, then blue, each most significant bit first.
- **Reset time** — How long the line must stay low to latch the colors: more than 50 µs for the original WS2812B, and more than 280 µs for newer revisions and many compatible LEDs.

## Going deeper
### Generating the timing
At 800 kbit/s each bit is only 1.25 µs, and the high time must be within about 150 ns. Common tricks avoid toggling a pin by hand: an SPI peripheral running at about 2.4 MHz sends each WS2812 bit as three SPI bits (100 for a 0 and 110 for a 1); a timer’s PWM output with DMA changes the duty cycle every period; and some microcontrollers, such as the RP2040 with its programmable I/O, generate the waveform in hardware.
### Reset time
The original WS2812B datasheet asks for the line to stay low for more than 50 µs to latch the colors. Later revisions and many compatible LEDs need more than 280 µs, so libraries commonly wait at least 280 µs to be safe.
